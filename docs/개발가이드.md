*(Master Unified Development & Integration Guide)*

## 1. 시스템 위상 및 핵심 책임 (Single Source of Truth)

세 시스템(BestERP, BestClubVN, 가맹점 쇼핑몰)은 독립 배포·운영되지만, **동일한 Firebase 프로젝트(`jumper-b15aa`) 인프라와 단일 데이터 규격**으로 실시간 연동됩니다.

| 시스템 | 기준 역할 | 핵심 책임 및 데이터 소유권 |
|---|---|---|
| **BestERP** | **가맹점 SaaS · CRM · ERP** | • **상품 카탈로그 마스터(Single Source of Truth)**: 상품 생성·수정·상태 관리 단독 소유<br>• 가맹점 멀티테넌트 관리, 직원/고객 매핑, 현장 주문 접수<br>• **이벤트 쿠폰·바우쳐 오프라인 현장 검증/승인**<br>• AI 경영지원(ERM): 일일 업무 보고, 지연 업무 알림, 매출 분석 |
| **BestClubVN** | **통합 멤버십 · 지갑 · 플랫폼** | • **통합 회원(User) 원장**, BM 지갑, 보너스 티켓(BT), 룰렛/포인트 리워드<br>• 통합 쇼핑몰(`/mall.html`), 이벤트 라운지(`/events.html`)<br>• 가맹점 웹진 위젯(`kca_webzine_widget.html`) 호스팅 |
| **가맹점 쇼핑몰** | **고객 판매/서비스 채널** | • 고객 상품 조회, 장바구니, 주문/결제 접수 (예: BEST WINNER, 대한김치 등)<br>• BestERP에서 공개(`published`)한 상품을 실시간 동기화하여 표시 |
| **Firebase / Functions** | **공유 인프라 및 트랜잭션** | • **프로젝트 ID: `jumper-b15aa`**<br>• 공통 Firestore 원장, Cloud Functions(결제/수수료 검증, 쿠폰 오프라인 승인) |

> ⚠️ **절대 규칙:** BestERP는 독자적인 별도 회원 DB나 상품 DB를 분리하여 파편화하지 않으며, **동일한 Firebase 프로젝트(`jumper-b15aa`)의 Firestore 원장 규격을 준수**해야 합니다.

## 2. 프론트엔드/백엔드 코딩 표준 (Harness Rules)

### 2.1 기술 스택 (Tech Stack)
* **Frontend**: HTML5, Vanilla JavaScript (ESM 모듈 방식), CSS3 (Tailwind 지양, **Custom Vanilla CSS 선호**)
* **Build Tool**: Vite (로컬 개발 서버 및 프로덕션 빌드 번들링)
* **Backend / Database**: Firebase v10 SDK (Auth, Firestore, Functions, Storage)

### 2.2 시스템 제어 및 보안/품질 규칙
1. **인코딩 철칙 (UTF-8 필수)**: Windows PowerShell 환경에서 텍스트 직접 치환 시 파일 인코딩(한글 깨짐) 주의. 대규모 파일 수정 시 Node.js 스크립트를 사용하여 UTF-8을 엄격히 유지합니다.
2. **글로벌 인증 가드 (Global Auth Guard)**: 신규 관리자 페이지 추가 시 `<script type="module">` 블록에 `checkAdminAuth()` 등 권한 검증 로직을 필수로 탑재하여 비인가 접근을 차단합니다.
3. **UI/UX Aesthetics (디자인 원칙)**:
   * 구글 폰트(Inter 등 모던 웹폰트) 고정 적용.
   * 다크모드, 글래스모피즘(Glassmorphism), 세련된 마이크로 인터랙션을 통해 프리미엄 ERP 룩앤필을 구현합니다.
   * 모바일/태블릿 환경(매장 POS 및 패드)에서도 매장 직원이 터치 기반으로 1초 안에 조작할 수 있는 직관적 반응형 UI를 제공합니다.
4. **Firebase 모듈화 (Repository Pattern)**: `services/` 폴더 내에 DB/API 래퍼를 구성하여 호출을 모듈화하고, CDN 인라인 하드코딩을 지양합니다.
5. **소스 복구 및 롤백 주의**: 롤백 전 작업 중인 `uncommitted changes`가 유실되지 않도록 확인/백업 후 진행합니다.

* **최고 관리자 (Super Admin)**: `daguri75@gmail.com` 또는 Firestore `admins/{uid}` / `role in ['SUPER_ADMIN', 'admin']`
* **BEST WINNER 공식 가맹점 점주**: `hexttokenopbnb@gmail.com` (가맹점 ID: `1791605366`)  
  *(※ 주의: `hexttokenopbnb@gmail.com`은 최고관리자가 아닌 BEST WINNER 가맹점의 점주 권한입니다)*
* **기타 주요 가맹점 ID**:
  * `1791002036`: 대한김치
  * `1791605366`: BEST WINNER

### 3.2 🚨 [CRITICAL] 권한(Role) 네이밍 규칙: 'CEO' 통일
앞으로 온보딩되는 **모든 가맹점 점주(Merchant Owner)**에게 시스템 권한을 부여할 때, `ADMIN`이나 `admin` 등 파편화된 명칭을 절대 사용하지 마십시오.
1. 가맹점 점주 권한은 Firestore Users 컬렉션 및 Custom Claims에서 반드시 대문자 **`CEO`** 로 통일합니다.
2. `SUPER_ADMIN` (본사/플랫폼 개발사)을 제외한 모든 가맹점 대표는 `CEO` 롤을 통해 각자 가맹점 리소스에 접근합니다.
3. 향후 수백 개 가맹점으로 스케일업 시 Role 혼선이 발생하지 않도록 이 규칙을 엄격히 준수합니다.

### 3.3 테넌트 소속 검증 및 가맹점명 자동 표출
1. **인증 흐름**:
   * Firebase Authentication 로그인 성공 후 `user.email` 및 `user.uid` 확인.
   * `merchant_members` 컬렉션에서 `{normalized_email}_{merchantId}` 복합 키 또는 `users/{uid}`의 `merchantId` 조회.
2. **가맹점명 자동 표출 (필수 구현)**:
   * 점주가 로그인하면 BestERP 좌측 상단 헤더에 해당 점주의 **가맹점명(예: BEST WINNER)과 로고**가 자동으로 표출되어야 합니다.
3. **엄격한 테넌트 격리**:
   * URL 파라미터 변조 등으로 타 가맹점(`merchant_id`)의 상품, 주문, 매출 원장에 접근하는 것을 전면 차단합니다.
   * 모든 쿼리 및 보안 규칙에 `merchant_id` 조건을 필수로 적용합니다.

## 4. 🚨 [CRITICAL] Firestore 보안 규칙 (Rules) 사전 검증 의무화

새로운 컬렉션을 추가하거나, 백엔드 로직(생성/수정/삭제)을 개발한 이후에는 반드시 **클라이언트 단에서 `Missing or insufficient permissions` 에러가 발생하지 않는지 사전 검증**해야 합니다.
1. **신규 컬렉션 생성 시**: `firestore.rules`에 해당 `match` 블록이 누락되었는지 확인하고 반드시 룰을 추가 배포(`firebase deploy --only firestore:rules`)합니다.
2. **권한 계층 분리 시**: User, Admin, SuperAdmin, CEO(Merchant) 각 역할(Role)이 `create`, `update`, `delete`, `read` 오퍼레이션에서 차단당하지 않는지 Rule 시뮬레이터를 돌리거나 실제 계정으로 통과를 확인합니다.
3. 동일한 권한 에러를 반복하여 발생시켜 고객 및 점주 화면에 표출되는 것은 **엄중한 결함**으로 간주합니다.

## 5. 상품 카탈로그 마스터 규격 (BestERP 단독 소유)

상품의 최초 등록·수정·상태 관리는 **BestERP에서만 수행**합니다.  
BestERP에서 상품을 등록하고 상태를 `published`로 설정하면, **가맹점 자체 쇼핑몰과 BestClubVN 통합 쇼핑몰(`/mall.html`)에 실시간으로 동시 노출**됩니다.

### 5.1 4대 상품 타입
* `menu`: 식당 메뉴, 음료, 디저트, 세트 메뉴
* `physical_product`: 김치, 밀키트, 식자재, 생활용품 등 실물 배송 상품
* `service`: 설치, 수리, 인테리어, 클리닝, 컨설팅 등
* `booking`: 날짜/시간/인원 예약형 서비스

### 5.2 Firestore 컬렉션: `merchant_products/{productId}`

```json
{
  "product_id": "prod_1791605366_001",
  "merchant_id": "1791605366",
  "product_name": "베스트 프리미엄 세트",
  "description": "최상급 재료로 구성된 스페셜 패키지",
  "product_type": "physical_product",
  "category_id": "cat_special",
  "price": 120000,
  "currency": "VND",
  "options": [
    { "name": "기본형", "addPrice": 0 },
    { "name": "대용량 추가", "addPrice": 30000 }
  ],
  "sale_status": "published",
  "inventory": 100,
  "unit": "개",
  "SKU": "BW-SET-001",
  "images": [
    "https://images.unsplash.com/photo-..."
  ],
  "display_order": 1,
  "created_at": "Timestamp",
  "updated_at": "Timestamp"
}
```

* **상태값(`sale_status`)**:
  * `draft`: 작성중 (외부 미노출)
  * `published`: 공개/판매중 (쇼핑몰 실시간 노출)
  * `paused`: 일시중지 (노출 차단)
  * `sold_out`: 품절 (노출되나 구매 불가)
  * `archived`: 보관/판매 종료
* **화폐 단위**: 모든 기본 가격은 **VND(베트남 동, BM 기준 현금 가치)**로 등록합니다.

### 5.3 쇼핑몰 자동 동기화 및 결제 재검증 원칙
1. **API/DB 직접 연동**: HTML 스크래핑 방식 배제, BestERP가 제공하는 Firestore 리스너 및 공통 API를 통해 자동 동기화.
2. **서버 사이드 단가 재검증 (필수)**: 고객 브라우저에서 요청한 품목 가격 정보를 절대 신뢰하지 않고, **주문/결제 처리 시 서버(Cloud Functions)에서 DB 기준 가격 및 옵션을 100% 재검증**합니다.

## 6. 재화(BM/BT/Point/GP) 및 결제·수수료·정산 규칙

### 6.1 재화 명칭 표준화 (KM 폐기)
* **BM (VND)**: 플랫폼 내 유일한 현금성 결제·정산 재화 (**KM은 완전 폐기되었으므로 코드 및 UI에 절대 사용 금지**).
* **BT (Bonus Ticket)**: 가맹점에서 고객이 100,000 VND 결제 시마다 **1 BT 지급** (`Math.floor(amount / 100000)`).
* **Point**: 5% 캐시백 및 룰렛 등으로 획득하는 비현금성 리워드.
* **GP**: 게임 전용 포인트.

### 6.2 수수료 및 정산 공식
* **고객 결제**: 수수료 0%
* **가맹점 수수료**: **10%** (추천인 20%, 상위추천인 10%, 잭팟 풀 30%, 플랫폼 40%로 분배)
* **가맹점 실 매출액 (90%)**: 가맹점 원장 필드 `pendingSettlementVnd`에 누적 기록되며, 향후 **USDT 정산 파이프라인**을 통해 일괄 정산 처리됩니다.
* **BT 차감 원칙**: 결제 시 고객에게 BT가 지급되면, 가맹점의 `merchants.btBalance`에서 원자적으로 차감됩니다.

### 6.3 주문·결제 스냅샷 및 트랜잭션 멱등성
1. 주문 생성 시점의 상품명, 가격, 옵션 정보는 **주문 스냅샷(Snapshot)**으로 고정 저장하여 향후 상품 정보가 변경되어도 과거 주문 내역이 왜곡되지 않도록 합니다.
2. 재고 차감 및 결제 승인은 `runTransaction`을 통해 동시성 충돌을 방지하고 멱등성을 보장합니다.

## 7. 이벤트 쿠폰 & 바우쳐 현장 검증 시스템 (BestERP 필수 탑재)

BestClubVN(`/events.html`)에서 회원이 BM으로 구매하거나 무료로 발급받은 쿠폰/바우쳐를 매장에 방문하여 사용할 때, **BestERP에서 현장 승인**을 처리합니다.

### 7.1 현장 검증 프로세스
1. 고객이 마이페이지(`/mypage.html`)에서 쿠폰의 **QR 코드 또는 12자리 코드(`BC-XXXX-XXXX-XXXX`)** 제시.
2. BestERP 직원이 **쿠폰 검증 메뉴**에서 카메라로 QR을 스캔하거나 12자리 코드를 직접 입력.
3. Firebase Callable Function `redeemCouponOffline` 호출:
   ```javascript
   import { getFunctions, httpsCallable } from "firebase/functions";
   
   const functions = getFunctions();
   const fnRedeem = httpsCallable(functions, "redeemCouponOffline");
   
   const result = await fnRedeem({
     couponCode: "BC-A1B2-C3D4-E5F6",
     merchantId: myMerchantId // BestERP 로그인 가맹점 ID
   });
   ```
4. **서버 검증 로직**:
   * 쿠폰 상태가 `available`인지 확인
   * 유효기간(`expiresAt`) 경과 여부 확인
   * 해당 쿠폰의 `applicableMerchantIds`에 현재 가맹점이 포함되어 있는지 확인
   * 일치 시 `status: 'used'`, `redeemedAt: serverTimestamp()`, `redeemedMerchantId: myMerchantId`로 원자적 전환.

## 8. 가맹점 웹진(BestClub Webzine) 연동 위젯 가이드

BestERP 내에 가맹점주가 **본인 홈페이지에 삽입할 수 있는 웹진 위젯 설정 및 임베드 코드 복사 화면**을 제공합니다.

### 8.1 임베드 파라미터 규격
* **위젯 URL**: `https://bestclubvn.netlify.app/kca_webzine_widget.html`
* **파라미터**:
  * `merchant`: 가맹점 ID (예: `1791605366`)
  * `theme`: 가맹점 브랜드 색상 (URL 인코딩 hex, 예: `%237c3aed`)
  * `layout`: `card` (격자 카드형) / `banner` (가로 배너형) / `feed` (피드형)
  * `mode`: `light` / `dark`
  * `count`: 표출 기사 수 (기본: `4`)


## 9. AI 경영관리(ERM) 연동 및 휴먼-인더-루프(HITL) 원칙

BestERP는 단순 CRM/자재관리를 넘어 AI 경영지원(ERM Bot) 기능을 제공합니다.
* **기능 범위**: 일일 업무 보고 자동 요약, 지연/위험 업무 사전 감지, 고객 맞춤형 타겟 프로모션 제안.
* **⚠️ [CRITICAL] AI DB 조작 제어 (HITL)**:
  * **모든 AI에 의한 데이터 DB 조작(생성, 수정, 삭제)**은 AI가 자율적으로 커밋할 수 없습니다.
  * 반드시 시스템 관리자 또는 직원이 확인 모달/버튼을 통해 **명시적으로 승인(Human-in-the-Loop)한 후에만 Firestore Write가 실행**되어야 합니다.

## 11. BestERP AI가 지켜야 할 10대 개발 절대 원칙

1. **KM 단어 사용 금지**: 모든 결제·재화 표기는 **BM** 및 **VND**로 통일한다.
2. **DB 스키마 보존**: `merchant_products`, `merchants`, `merchant_members`, `user_coupons` 등의 컬렉션명과 핵심 필드명을 임의로 변경하지 않는다.
3. **가맹점 격리 (Tenant Isolation)**: 점주가 타 가맹점의 상품을 수정하거나 주문을 열람할 수 없도록 모든 쿼리에 `merchant_id` 조건을 필수로 건다.
4. **금액/수수료 조작 금지**: 결제 금액, 10% 수수료, 100,000 VND당 1 BT 지급 로직은 클라이언트가 임의 계산하지 않고 서버/원장 규칙을 따른다.
5. **더미 데이터 하드코딩 금지**: 화면에 목업/가짜 수치를 하드코딩하지 않고 실제 Firestore 원장 데이터와 바인딩한다.
6. **Single Source of Truth 준수**: 상품의 생성·수정은 BestERP에서만 수행하며, 가맹점 쇼핑몰이나 BestClubVN에 실시간 동기화되도록 이벤트/Firestore 리스너를 유지한다.
7. **수퍼 어드민 권한 오남용 방지**: `hexttokenopbnb@gmail.com`은 BEST WINNER 점주이며 최고관리자가 아니다. 최고관리자는 `daguri75@gmail.com`으로 엄격히 분리한다.
8. **트랜잭션 원자성**: 재고 차감, 쿠폰 사용 처리 시 `runTransaction`을 사용하여 동시성 충돌을 방지한다.
9. **반응형 UI 및 직관적 디자인**: 모바일 태블릿 환경(매장 POS 및 패드)에서도 매장 직원이 QR 스캔 및 주문 처리를 1초 안에 할 수 있도록 터치 친화적 UI를 제공한다.
10. **작업 전 사전 조사**: 기존 소스코드 및 관련 문서를 먼저 전수 조사한 후 코드를 작성한다.
